# Техническая документация проекта Zhukodav / Click Them All

## 1. Назначение проекта

Zhukodav, также отображаемый в `index.html` как `Click Them All`, это браузерная аркадная игра на PixiJS. Игрок нажимает на появляющихся жуков, избегает бомб, использует цветовые кнопки для цветных жуков и проходит уровни с возрастающей сложностью.

Проект выполнен как статическое web-приложение без сборщика: HTML-страница подключает PixiJS, GSAP, pixi-gif и основной ES-модуль `game.js`.

## 2. Технологический стек

- JavaScript ES modules.
- PixiJS для рендера canvas-сцены.
- GSAP для анимаций.
- Firebase SDK через CDN для анонимной авторизации, Firestore, Remote Config и сохранения прогресса.
- LocalStorage для локального статуса пройденных уровней.

Внешние библиотеки подключаются прямо в `index.html`:

```html
<script src="js/pixi.min.js"></script>
<script src="https://cdn.jsdelivr.net/npm/pixi-gif@1.0.0/dist/pixi-gif.min.js"></script>
<script src="https://cdnjs.cloudflare.com/ajax/libs/gsap/3.12.2/gsap.min.js"></script>
<script type="module" src="game.js"></script>
```

## 3. Структура проекта

```text

```

## 4. Запуск проекта

Так как используются ES-модули и CDN-зависимости, проект лучше запускать через локальный web-сервер, а не прямым открытием файла.

Пример:

```bash
python -m http.server 8000
```

После запуска открыть:

```text
http://localhost:8000
```

Для полной работы Firebase и CDN-зависимостей нужен доступ к сети. Базовая игра может работать локально, если загружены нужные скрипты и ассеты.

## 5. Главные модули

### `index.html`

Минимальная HTML-обвязка. Задает фон, canvas-стили и подключает зависимости.

### `game.js`

Главный файл проекта. Отвечает за:

- создание `PIXI.Application`;
- загрузку текстур;
- главное меню и выбор уровней;
- построение игрового поля;
- адаптивную раскладку;
- очередь объектов;
- спавн жуков и бомб;
- обработку кликов;
- игровые эффекты;
- паузу, победу и поражение;
- синхронизацию с Firebase.

Ключевые функции:

- `startLevel(index)` - запуск уровня.
- `setupPlayArea()` - построение игрового поля и UI текущего режима.
- `prepareObjectQueue()` - генерация очереди игровых объектов.
- `scheduleNextSpawn(delay)` - планирование следующего появления объекта.
- `spawnObject()` - создание Pixi-контейнера жука/бомбы на поле.
- `startLifetimeCheck(obj)` - контроль времени жизни объекта.
- `syncObjectLifetime(obj, now)` - пересчет оставшегося времени жизни с учетом замедления.
- `decrementClickCounter(container, data)` - уменьшение счетчика кликов у многокликовых объектов.
- `animateRemoveObject(container, onAfterRemove)` - удаление объекта по клику.
- `removeExpiredObject(obj)` - удаление объекта по истечении времени жизни.
- `endGame(won)` - завершение уровня.
- `showPausePopup()` и `resumeGame()` - пауза и продолжение.

### `levels.js`

Экспортирует массив уровней:

```js
const levels = [
  {
    id: 1,
    goalBugCount: 10,
    lifeCount: 5,
    params: {
      maxObjects: 3,
      lifetimeMultiplier: 1.1,
      spawnMultiplier: 0.9,
      spawnWeights: {
        bug: 1
      }
    }
  }
];

export default levels;
```

Поля уровня:

- `id` - номер уровня.
- `goalBugCount` - сколько очков/жуков нужно набрать для победы.
- `lifeCount` - стартовое количество жизней.
- `params.maxObjects` - максимальное количество активных объектов на поле.
- `params.lifetimeMultiplier` - множитель времени жизни объектов.
- `params.spawnMultiplier` - множитель частоты появления.
- `params.spawnWeights` - веса типов объектов в очереди спавна.
- `introPopup` - необязательное обучение перед уровнем.

Важно: в текущих данных используется поле `descryption`. Название написано с ошибкой, но код ожидает именно его, поэтому переименование потребует правки логики попапов.

### `bug-config.js`

Содержит базовый баланс каждого типа объекта:

- `lifetime` - базовое время жизни в миллисекундах.
- `spawnInterval` - базовая задержка до следующего спавна.
- `clicks` - количество нужных кликов.
- `scoreValue` - сколько очков дает объект.
- `healAmount` - сколько жизней лечит объект, если применимо.
- `spawnZone` - зона появления: `left`, `right` или `full`.

Финальные параметры на уровне считаются в `game.js` через `getRuntimeBugBalance(type)`:

```text
runtime lifetime = base lifetime * level lifetimeMultiplier * frozen multiplier
runtime spawnInterval = base spawnInterval / level spawnMultiplier
```

### `js/game-ui.js`

Содержит чистые UI-хелперы:

- определение desktop/mobile режима;
- расчет адаптивной раскладки;
- построение header UI;
- создание панелей;
- обновление счетчика цели и жизней;
- overlay для мобильной портретной ориентации.

Этот файл не управляет игровым состоянием, а возвращает layout-данные и Pixi UI-элементы.

### `js/progress-ui.js`

Содержит визуальную часть экрана прогресса игрока. Экран является основным игровым hub после главного меню:

```text
Главное меню -> Экран прогресса -> PLAY -> Первый непройденный уровень -> Игра
```

Дополнительно при `showLevelSelectButton: true` экран показывает вторичную кнопку `ВЫБОР УРОВНЯ`, которая открывает существующий level select для разработки и тестирования.

Модуль строит Pixi-сцену с фоном `bg_game`, центральной карточкой, кнопкой `play.png`, вторичной кнопкой выбора уровней и программным силуэтом жука из 120 квадратных клеток. Каждая непустая клетка маски соответствует одному уровню: `progressCells[0]` - уровень 1, `progressCells[119]` - уровень 120.

Важно: `progress-ui.js` не читает LocalStorage, не выбирает следующий уровень и не обращается к Firebase. Он получает список завершенных уровней и callbacks из `game.js`. Навигация остается в `game.js`: `continueGameFromProgress()` запускает первый реально существующий непройденный уровень, а `showLevelSelect()` открывает технический список уровней.

### `firebase.js`

Отвечает за backend-интеграцию:

- `initBackend()` - анонимная авторизация и Remote Config.
- `fetchRemoteLevel(levelId)` - загрузка уровня из Firestore.
- `saveProgress(levelId, score, won)` - сохранение прогресса.
- `trackEvent(name, props)` - запись аналитического события.
- `createLevelAttempt(data)` - создание аналитической записи попытки уровня в `levelAttempts`.
- `finishLevelAttempt(attemptId, result)` - закрытие аналитической записи попытки уровнем, результатом и длительностью.
- `recalcLeaderboard(totalLevels)` - пересчет лидерборда.
- `rcNumber(key, fallback)` - чтение числового Remote Config параметра.

### `autoBalanceFeedback.js`

Вспомогательный скрипт для грубой оценки сложности уровней. Использует веса типов и cost-модель. Важно: в текущем коде скрипта есть несовпадение со структурой `levels.js`: он читает `level.spawnWeights`, а актуальные веса лежат в `level.params.spawnWeights`. Если использовать этот скрипт дальше, его нужно синхронизировать с текущим форматом уровней.

## 6. Игровой цикл

1. Загружается страница `index.html`.
2. `game.js` создает Pixi-приложение и загружает текстуры.
3. Пользователь попадает в главное меню.
4. Главная кнопка `PLAY` открывает экран прогресса.
5. Кнопка `play.png` на экране прогресса вызывает `continueGameFromProgress()`.
6. `continueGameFromProgress()` через `getNextPlayableLevelIndex()` ищет первый непройденный индекс в актуальном массиве `levels`.
7. Если следующий уровень найден, вызывается `startLevel(index)`.
8. Если все существующие уровни пройдены, показывается небольшой popup `ВСЕ УРОВНИ ПРОЙДЕНЫ!`.
9. Вторичная кнопка `ВЫБОР УРОВНЯ`, если включена, открывает существующий level select.
10. `startLevel(index)` сбрасывает состояние, строит игровое поле и запускает очередь спавна.
11. `prepareObjectQueue()` создает очередь объектов по весам `spawnWeights`.
12. `scheduleNextSpawn()` планирует появление объекта.
13. `spawnObject()` создает Pixi-контейнер, добавляет спрайт, счетчик кликов, индикатор жизни и обработчик `pointerdown`.
14. `startLifetimeCheck()` и ticker индикатора времени отслеживают истечение времени жизни.
15. При правильном клике объект удаляется, начисляется score и обновляется UI.
16. Уровень завершается победой при `score >= goalBugCount`, поражением при `life <= 0`.
17. Кнопки меню после уровня и из паузы возвращают игрока на экран прогресса.

## 7. Типы объектов

### `bug`

Обычный жук. Удаляется одним кликом, дает очки.

### `bomb`

Бомба. При клике отнимает жизнь. Не является целью для победы.

### `fat`

Толстый жук. Требует несколько кликов. Над жуком отображается счетчик оставшихся кликов; после последнего клика счетчик исчезает.

### `coloredBug_red`, `coloredBug_blue`, `coloredBug_green`, `coloredBug_yellow`

Цветные жуки. Для клика игрок должен удерживать соответствующую цветовую кнопку. В игре синий цвет UI представлен как фиолетовая кнопка/жук.

### `fatColoredBug_*`

Цветной толстый жук. Совмещает механику удержания цвета и несколько кликов.

### `frozen`

Морозный жук. При клике запускает эффект замедления:

- замедляет анимации активных объектов;
- замедляет расход времени жизни;
- показывает голубую волну;
- показывает голубую рамку-таймер действия эффекта.

### `chameleon`

Хамелеон. Временно разрешает кликать по цветным жукам без удержания цветовой кнопки. Показывает радужную подложку поля и радужную рамку-таймер.

### `neat`

Чистильщик. Очищает поле от активных объектов и временно задерживает новый спавн.

### `healer`

Лечащий объект. При клике добавляет жизнь, но не выше максимума уровня.

## 8. Система времени жизни объектов

Каждый объект получает:

- `totalLifetimeMs` - исходная длительность жизни;
- `remainingLifetimeMs` - оставшееся время;
- `lastLifetimeSyncAt` - последний момент синхронизации.

Время списывается через `syncObjectLifetime(obj, now)`. Если активен морозный эффект, часть прошедшего времени считается с множителем `FROZEN_LIFETIME_RATE`.

Визуальный индикатор жизни создается через `addLifetimeIndicator(container)`. Это тонкая полоска под жуком без чисел. Она обновляется через Pixi ticker и очищается при удалении объекта.

## 10. UI и адаптивность

Проект поддерживает:

- desktop layout;
- mobile landscape layout;
- блокирующий overlay для mobile portrait.

Режим определяется через `getViewportMode()` из `js/game-ui.js`. При ресайзе вызывается `rebuildUI()`, который:

- сохраняет score, lives, очередь и активные объекты;
- пересоздает игровое поле;
- переносит активные объекты в новое поле;

## 12. Экран прогресса

Экран прогресса создается в `showProgressScreen()` и визуально реализован в `js/progress-ui.js`.

Основные правила:

- используется существующий фон `images/ui/custom/bg_game.png`;
- используется существующая графическая кнопка `images/ui/custom/play.png`;
- силуэт жука строится программно через маску 18 x 16;
- непустых клеток в маске строго 120;
- непройденные клетки всегда видны нейтральным цветом;
- пройденные уровни окрашивают соответствующие клетки в цвета маски;
- источник прогресса - существующий `completedLevels` в LocalStorage;
- повторное прохождение уровня не окрашивает дополнительные клетки;
- `PLAY` означает продолжить прохождение и напрямую запускает первый непройденный уровень;
- следующий уровень ищется по первому индексу массива `levels`, отсутствующему в `completedLevels`;
- поиск не использует `completedLevels.length` и не использует `Math.max(...completedLevels) + 1`;
- если все существующие уровни пройдены, `PLAY` показывает popup и не вызывает `startLevel(-1)`;
- вторичная кнопка `ВЫБОР УРОВНЯ` включается/выключается настройкой `showLevelSelectButton` в `PROGRESS_SCREEN_CONFIG`;
- экран не меняет Firebase API, баланс, уровни и игровую механику.

При resize экран пересчитывает собственный layout через `layoutProgressScreen()`. Для mobile portrait используется существующий orientation overlay проекта.

Карточка прогресса центрируется относительно всего viewport и не учитывает кнопки при расчете позиции. Кнопки находятся в отдельном слое `progressControlsLayer` и позиционируются независимо: `PLAY` закреплен справа внизу, а `ВЫБОР УРОВНЯ` располагается слева от него.

## 14. Как добавить новый тип жука

1. Добавить базовый баланс в `BUG_BALANCE` в `bug-config.js`.
2. Добавить спрайт в `images/`.
3. Добавить текстуру в список загрузки в `game.js`.
4. Добавить ветку создания визуала в `spawnObject()`, если новый тип требует отдельной картинки или размера.
5. Добавить обработку клика в `spawnObject()`, если поведение отличается от обычного жука.
6. Добавить тип в `spawnWeights` нужных уровней.
7. При необходимости добавить `introPopup` в `levels.js`.
8. Обновить `autoBalanceFeedback.js`, если тип должен учитываться в анализе сложности.

## 15. Как добавить уровень

Добавить объект в массив `levels`:

```js
{
  id: 81,
  goalBugCount: 75,
  lifeCount: 10,
  params: {
    maxObjects: 5,
    lifetimeMultiplier: 1,
    spawnMultiplier: 1.2,
    spawnWeights: {
      bug: 1,
      fat: 0.5,
      frozen: 0.2
    }
  },
  introPopup: {
    type: "frozen",
    descryption: "Нажми на морозного жука, чтобы замедлить остальных!"
  }
}
```

Правила:

- `id` должен идти последовательно.
- Веса в `spawnWeights` не обязаны суммироваться в `1`; они используются как относительные веса.
- Если уровень вводит новую механику, лучше добавить `introPopup`.
- Не стоит резко повышать одновременно `maxObjects`, `spawnMultiplier` и долю многокликовых/цветных жуков.

## 17. Аналитика попыток уровня

Попытки уровня пишутся в Firestore collection `levelAttempts`.

Клиентское состояние в `game.js`:

- `BALANCE_VERSION` - версия баланса, которую нужно менять при существенных изменениях `levels.js`.
- `currentAttemptId` - Firestore id текущей попытки.
- `currentAttemptPromise` - pending создание документа, если `addDoc()` еще не завершился.
- `currentAttemptStartedAt` - локальное время старта для расчета `durationMs`.
- `currentAttemptNo` - локальный номер попытки уровня.
- `currentAttemptClosed` - защита от повторного закрытия.

Попытка создается в `beginLevelAttempt()` внутри `startSpawning()`, то есть после закрытия обучающего intro popup и перед первым спавном. Это означает, что просмотр обучения не считается попыткой.

Попытка закрывается через `closeLevelAttempt(status, exitReason)`:

- победа: `status = win`;
- поражение: `status = loss`;
- пауза -> заново: `status = exit`, `exitReason = restart`;
- пауза -> меню: `status = exit`, `exitReason = pause_menu`.

При закрытии значения `score`, `life`, `levelData.goalBugCount` и `durationMs` снимаются синхронно до асинхронной отправки в Firebase, чтобы следующий уровень не перезаписал результат текущей попытки.

## 18. Проверка изменений

Минимальная проверка JavaScript-синтаксиса:

```bash
node --check game.js
```

Если менялся экран прогресса:

```bash
node --check js/progress-ui.js
```

Для проверки игровых изменений:

1. Запустить локальный сервер.
2. Открыть игру в браузере.
3. Проверить desktop и mobile landscape размеры.
4. Проверить нужные уровни с новыми типами/весами.
5. Проверить паузу, ресайз окна, победу и поражение.

## 19. Известные технические особенности

- `game.js` является большим монолитным файлом. При дальнейшем росте проекта стоит постепенно выносить подсистемы: spawn, object behavior, effects, popups, assets.
- В нескольких старых комментариях видна битая кодировка. Это не влияет на выполнение, но затрудняет сопровождение.
- Поле `descryption` в `levels.js` написано с ошибкой, но является частью текущего контракта данных.
- `autoBalanceFeedback.js` нуждается в обновлении под актуальную структуру `levels.js`.
- Firebase SDK и часть библиотек загружаются с CDN, поэтому offline-режим ограничен.
- Если игрок закрывает вкладку во время уровня, запись `levelAttempts` может остаться в статусе `in_progress`; это ожидаемое поведение и полезный сигнал оборванной сессии.

- Привести комментарии и старую документацию к UTF-8.
- Синхронизировать `autoBalanceFeedback.js` с текущим форматом уровней.
- Добавить единый registry типов объектов, чтобы визуал, баланс и поведение нового жука описывались в одном месте.
