# Кусочки блюд и сборка

Пицца доступна сразу. Остальные блюда открываются после получения всех уникальных частей и ручной сборки. Число частей и здоровье берутся из конфигурации блюда (`maxLives`). Существующие изображения частей служат также масками целевых мест. Салаты собираются в порядке `assemblyOrder`.

Автор задаёт награды в `levels.js`, например:

```js
lootRequired: true,
loot: [{ id: 'cake-first', type: 'foodPiece', foodId: 'cake', pieceId: 'cake_01' }],
```

`id` записи награды должен оставаться стабильным. Победа записывается вместе с коллекцией в `foodPuzzleProgress.v1` до показа результатов. Уже награждённый уровень не выдаёт новый лут после изменения конфигурации. Поражение награды не выдаёт. Старые открытия по уровню больше не действуют; стартовая пицца остаётся доступной.

Распределение наград намеренно не придумано: автор должен назначить все части нестартерных блюд. Для проверки из консоли браузера:

```js
const { validateFoodLoot } = await import('./js/food-progress.js');
const { default: levels } = await import('./levels.js');
console.table(validateFoodLoot(levels));
```

Проверка выявляет неизвестные и повторные части, отсутствующий обязательный лут и недостижимые комплекты. Пока таблица назначений пуста, все пять новых блюд недостижимы. Проверку следует выполнять перед выпуском.

Сохранение коллекции и сборки локальное, в браузере. Серверная синхронизация коллекции не добавлена. Выбор блюда продолжает использовать существующее сохранение предпочтения, но на другом устройстве требуется локально собранное блюдо.

Проверка сценариев: `node tests/browser-gameplay.cjs --food-puzzle`.
